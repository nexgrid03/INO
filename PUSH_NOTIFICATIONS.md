# Reminder Push Notifications (FCM)

Every reminder has an exact due **date and time** (`reminders.due_at`). It is
rung two ways, both under the same notification id so they never stack:

1. **On the device, at the exact moment** — `ReminderScheduler` arms a local
   scheduled notification (`flutter_local_notifications.zonedSchedule`) when a
   reminder is created / restored / loaded. Works offline and with the app
   killed; survives reboots via the boot receiver in `AndroidManifest.xml`.
2. **From the server, as a backup** — a per-minute Supabase cron calls
   `send-reminder-push`, which pushes every reminder whose `due_at` has
   arrived and has no `notified_at` yet. The message is **data-only**; the app
   renders it itself (`PushService` / `inoFirebaseBackgroundHandler`) so a
   phone that already rang just gets its banner refreshed.

**Firebase is only the delivery pipe** — the reminders live in `public.reminders`
and never leave Supabase.

```
pg_cron (every minute)
   └─> Edge Function: send-reminder-push
         ├─ reads public.reminders   (due_at <= now(), notified_at is null)
         ├─ reads public.device_tokens
         ├─ POST fcm.googleapis.com/v1/…/messages:send   (data-only)
         └─ prunes dead tokens, stamps reminders.notified_at
                     │
                     ▼
             FCM ──> device ──> PushService ──> reminder detail sheet
```

## Remaining setup

### 1. Deploy the database changes

```bash
supabase db push
```

### 2. Generate the Firebase service account key

Firebase Console → ⚙️ **Project settings → Service accounts → Generate new
private key** → downloads a JSON file.

> **This file is a credential.** It can send push to every INO user. Never
> commit it; store it in your password manager and delete the download.

```bash
supabase secrets set FCM_SERVICE_ACCOUNT="$(cat ~/Downloads/inoapp-b0101-firebase-adminsdk-xxxxx.json)"
```

### 3. Deploy the Edge Function

```bash
supabase functions deploy send-reminder-push
```

Test it immediately, before wiring the cron — create a reminder due one minute from now, wait for that minute, then:

```bash
curl -X POST "https://<project-ref>.supabase.co/functions/v1/send-reminder-push" \
     -H "Authorization: Bearer <service-role-key>"
```

Expected: `{"ok":true,"reminders":1,"sent":1,"pruned":0}`.
`"sent":0` with `"reminders":1` means no device token is registered — sign in on
a real device first.

### 4. Schedule it

Supabase Dashboard → **Database → Extensions** → enable `pg_cron` and `pg_net`.
Then in the SQL editor (the old daily `reminder-push` job must go — it would
re-notify on the day at 09:00):

```sql
select cron.unschedule('reminder-push');   -- ignore "could not find" if never created
select cron.schedule(
  'reminder-push-due',
  '* * * * *',                        -- every minute
  $$
  select net.http_post(
    url     := 'https://<project-ref>.supabase.co/functions/v1/send-reminder-push',
    headers := '{"Authorization": "Bearer <service-role-key>", "Content-Type": "application/json"}'::jsonb
  );
  $$
);
```

Verify with `select * from cron.job;` and check runs in `cron.job_run_details`.

### 5. iOS (needs a Mac + paid Apple Developer account)

Not required for Android to work.

1. Download `GoogleService-Info.plist` from Firebase Console → Project settings →
   your iOS app → and drop it into `ios/Runner/` **via Xcode** (so it is added to
   the target, not just the folder).
2. developer.apple.com → **Keys → +** → tick **Apple Push Notifications service**
   → register → download the `.p8`. **It can only be downloaded once.**
3. Firebase Console → **Cloud Messaging → APNs Authentication Key → Upload**
   (needs the `.p8`, its Key ID, and your Team ID).
4. Xcode → Runner target → **Signing & Capabilities** → add **Push Notifications**
   and **Background Modes ▸ Remote notifications**.

## Testing checklist

Push does not work on the Android emulator without Play Services, and is
unreliable on the iOS Simulator. **Use a real device.**

1. Run the app, sign in, and find the token in the logs (`push: token → …`).
2. Firebase Console → **Messaging → Send test message** → paste the token.
   - App **killed** → appears in the tray.
   - App **backgrounded** → appears in the tray.
   - App **foregrounded** → still appears (this is the `flutter_local_notifications`
     bridge; if it fails here but works backgrounded, the channel id has drifted).
3. Tap a notification → opens the reminders list.
4. Create a reminder two minutes out and put the phone down → it rings at that
   minute (local schedule). Tapping it opens **that reminder's** sheet.
5. Invoke the function manually after the due minute → `"sent":1`, and the
   banner is replaced, not duplicated. Run it again → `"sent":0` (the
   `notified_at` guard).
6. **Account isolation:** sign out, sign in as a different user, and invoke the
   function with user A having a due reminder. User B's phone must receive
   nothing.

## Notes and gotchas

**The channel id is load-bearing.** `PushService.channelId`, the
`default_notification_channel_id` meta-data, and `ANDROID_CHANNEL` in the Edge
Function must all read `ino_reminders`. Android 8+ silently discards a
notification aimed at a channel that does not exist — no error, no log.

**Channel importance is fixed at creation.** If you install the app, then later
change `Importance.high`, the existing install keeps the old importance. Uninstall
and reinstall to see the change.

**The legacy FCM API is dead.** Any tutorial using a `key=AAAA…` header against
`fcm.googleapis.com/fcm/send` is pre-2024 and will 404. This function uses HTTP
v1 with an OAuth2 bearer token minted from the service account.

**Token cleanup on sign-out is a privacy control, not housekeeping.**
`AuthService.signOut` deletes the token *before* `supabase.auth.signOut()`,
because the delete is authorised by an RLS policy on `auth.uid()`. Moving it
after would leave the row behind and this phone would keep receiving the previous
account's reminders. There is a test for this in the checklist above.

**App id.** The Firebase apps are registered to `com.example.inoapp`. Google Play
rejects `com.example.*`, so before release you must add a *new* Android app in the
same Firebase project under the real id and re-run `flutterfire configure`.
That also means issuing a new Google Sign-In OAuth client for the new package
name + SHA-1.

**Notifications the app derives itself** (expiring documents, backup health,
security posture) still come from `NotificationCenter` and are unrelated to FCM.
A push refreshes that feed so the bell badge and the tray agree.
